SETUP — do these in order (about 10 minutes)

1) SUPABASE   -> SQL Editor -> New query -> paste and Run, one file at a time:
                 supabase/auto-keys-schema.sql      (customer keys with USD balance)
                 supabase/auto-comment-jobs.sql     (queue for customers' custom comments)
2) GITHUB     -> upload everything in this folder to your repo, keeping the folders:
                 api/auto.js, lib/auto/*, supabase/*, vercel.json,
                 index.html, script.js, style.css (unchanged), auto-key.css, neon.css,
                 admin.html, auto-admin.html
               If your repo already has api/admin/auth.js it can stay (or be deleted); api/auto.js now also answers /api/admin/auth.
3) VERCEL     -> Settings -> Environment Variables must contain:
                 ADMIN_PASSWORD, ADMIN_SESSION_SECRET, PROVIDER_ENCRYPTION_KEY,
                 SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY
               (optional) RENDER_PROXY_URL  — only if your scheduler isn't https://kmpanel.onrender.com
               Change an env value -> Deployments -> Redeploy.
4) ADMIN      -> yoursite/auto-admin
                 a) Master Providers: add your panels (API url + key)
                 b) Service Mapping: for views, likes, shares, saves, reposts, comments pick the service
                    and set the CUSTOMER RATE in dollars per 1000. A service with no rate is hidden from customers.
                 c) Customer Keys: type the dollars (1, 2, 5...) -> Create key -> send it to the customer.
5) CUSTOMER   -> site -> Order -> Auto -> pastes the key -> orders. Balance drops with every order;
                 at $0 the key deactivates by itself.

CUSTOM COMMENTS (important)
 - The external scheduler (kmpanel.onrender.com) cannot carry the comment text, so views/likes/share/save/repost
   still go through it, but the customer's comments are queued in Supabase (auto_comment_jobs) and sent to the
   provider by THIS server (lib/auto/commentWorker.js, started from server.js) at the planned time.
 - The server must be awake at that time. On Render's Free plan a service sleeps after ~15 minutes without visits,
   and comments would go out late. Use a paid instance, or ping https://YOURSITE/healthz every 10 minutes
   (for example with UptimeRobot) to keep it awake.
 - Render logs show "[comments] custom-comments worker started" at boot. If you see
   "[comments] worker error ... did you run supabase/auto-comment-jobs.sql?" the SQL step was skipped.
 - A comment part that fails after 3 tries is refunded to the customer's key automatically.
   Look at Supabase -> Table Editor -> auto_comment_jobs (status, error, provider_order_id) to follow each part.
